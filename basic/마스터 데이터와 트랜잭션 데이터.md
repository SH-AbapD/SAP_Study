# 마스터 데이터와 트랜잭션 데이터

SAP에서 마스터 데이터(Master Data)는 여러 업무에서 반복해서 참조하는 기준 정보이고, 트랜잭션 데이터(Transaction Data)는 개별 업무를 처리하면서 생기는 기록

## 마스터 데이터란?

FI의 소모품비 계정을 예로 들면, 계정번호, 계정명, 계정 유형을 G/L 계정 마스터에서 관리. 서로 다른 날에 소모품을 구매해도 같은 성격의 비용이면 각 전표에서 같은 계정을 참조. 
CO의 코스트센터, SD의 고객, HR의 직원, MM의 자재, PP의 BOM도 같은 방식으로 여러 업무에서 재사용

## 트랜잭션 데이터란?

트랜잭션 데이터는 업무를 처리한 내용을 담음. 회계 전표에는 전기일, 계정, 금액, 차변/대변 구분이 기록.
판매오더에는 주문한 제품과 수량이, 생산오더에는 생산할 제품과 수량이 기록.
같은 고객이 같은 제품을 다음 달에 다시 주문하면 고객과 제품 정보는 재사용하고, 새 주문은 별도 판매오더로 기록.

## FI 전표로 보는 두 데이터의 관계

회사코드 1000의 총무팀이 소모품을 사고 현금 50,000원을 지급했다고 가정
```
| 구분 | 예시 | 역할 |
|---|---|---|
| 조직 단위 | 회사코드 1000 | 어느 회사코드의 장부에 전기할지 지정 |
| 마스터 데이터 | 소모품비 계정, 현금 계정, 총무팀 코스트센터 | 전표에서 참조할 계정과 비용 귀속 단위를 제공 |
| 트랜잭션 데이터 | 이번 회계 전표 | 전기일과 함께 차변에 소모품비 50,000원, 대변에 현금 50,000원을 기록. 소모품비 라인에 총무팀 코스트센터를 지정. |
```
이 전표를 FI에서는 어느 계정에 얼마를 기록했는지, CO에서는 어느 코스트센터에 비용이 발생했는지 확인하는 데 사용 가능. 
총무팀이 다음 달에 소모품을 다시 사면 같은 계정과 코스트센터를 참조하고, 새 거래는 별도 전표에 기록.

## 모듈별 예시
```
| 모듈 | 마스터 데이터 | 트랜잭션 데이터 |
|---|---|---|
| FI ( 재무회계 ) | G/L 계정 | 회계 전표, 지급·수금 전표 |
| CO ( 관리회계 ) | 코스트센터, 이익센터 | 실제 원가 전기, 배부 실행 결과 |
| SD ( 판매 및 유통 ) | 고객, 제품 | 판매오더, 출고 문서, 청구 문서 |
| HR ( 인사관리 ) | 직원 기본정보, 조직 배정 정보 | 근태 기록, 급여 계산 결과 |
| MM ( 자재관리 ) | 자재, 공급업체, 구매정보레코드 | 구매오더, 입고 자재문서 |
| PP ( 생산계획 ) | BOM, 작업장(Work Center), 공정 경로(Routing) | 생산오더, 생산실적 |
```
PP에서 BOM은 제품을 만드는 데 필요한 구성품과 수량을 정의. 생산오더는 이번에 어떤 제품을 몇 개 만들지 기록하고, 생산실적에는 실제로 몇 개를 만들었는지 남음. 같은 제품을 다시 생산할 때 기존 BOM을 참조해 새 생산오더를 생성 가능.

## 감사/추적용으로 남기는 수정용 데이터도 트랜젝션 데이터인가?

그렇다. 회계상 이미 전기한 금액이나 계정에 오류가 있다면, SAP는 원전표를 남긴 상태에세 회계 효과를 상쇄하는 별도 전표를 생성.( 역분개 )
원전표와 역분개 전표의 관계를 따라가면 어떤 전기가 취소되었는지 확인 가능

아까 예시에서 실제로 50,000원을 지급했는데 55,000원으로 잘못 전기했다면, 역분개 후 재전기하는 경우에는 다음 세 전표가 남음.

| 전표 | 역할 |
|---|---|
| 원전표 | 소모품비 55,000원을 기록 |
| 역분개 전표 | 원전표의 55,000원 전기 효과를 상쇄 |
| 재전기 전표 | 실제 지급액인 50,000원을 기록 |

세 전표 모두 회계 업무에서 발생한 트랜잭션 데이터. 역분개는 취소를 기록하고, 재전기는 올바른 금액을 기록.

반면 전표의 변경이력(Change History)은 변경이 허용된 필드를 누가 언제 어떻게 바꿨는지 추적하는 감사 데이터로 구분.
예를 들어 설정상 변경 가능한 전표 텍스트를 고치면 변경이력이 남고, 계정이나 전기 금액처럼 잔액에 영향을 주는 필드는 전기 후 직접 변경 불가.

ex)
설명만 잘못 적은 경우 : 해당 필드의 변경이 허용된 경우, 같은 전표에서 11월 소모품을 11월 총무팀 소모품으로 수정 가능.
                      장부에 기록된 금액은 그대로 50,000원이고, 변경이력에는 누가, 언제 설명을 변경하였는지 기록. 이때의 경우 전표는 그대로 한장.

금액을 잘못 적은 경우 : 실제 지급액이 55,000원이었다면, 이미 전기된 50,000원을 같은 전표에서 바로 수정 불가. 역분개 후 재전기 하는 경우
                      원전표 50,000원 -> 역분개 전표로 50,000원 상쇄 -> 새 전표 55,000 순서로 기록이 남음

## 요약

두 데이터를 구분하는 기준은 변경 빈도보다 업무에서 맡는 역할. 직원의 부서 정보는 인사 발령으로 바뀔 수 있어도 여러 인사 업무에서 참조하는 마스터 데이터. 그 직원의 이번 달 근태 기록은 해당 기간의 업무 활동을 담은 트랜잭션 데이터.
