# Data Element의 의미와 재사용

Data Element는 필드에 어떤 값을 담는지 정의하고, 같은 의미를 가진 필드에서 그 정의를 재사용할 수 있게 한다. 

## 같은 의미라면 Data Element를 재사용

FI 전표 테이블과 전표 조회 구조에는 모두 회사코드 필드가 필요.
전표 테이블은 값을 저장하고 조회 구조는 화면에 보여줄 값을 담지만, 두 필드가 나타내는 것은 모두 해당 전표가 속한 회사코드임.

| 사용하는 곳 | 필드 | 재사용하는 정의 |
|---|---|---|
| FI 전표 테이블 | company_code | 회사코드 Data Element |
| FI 전표 조회 구조 | company_code | 회사코드 Data Element |

같은 Data Element를 참조하면 기술적 타입과 함께 회사코드라는 라벨과 필드 설명도 한곳에서 관리 가능함.
화면이 DDIC 정보를 가져다 쓰면 같은 라벨이나 도움말을 활용할 수 있음.

## 형식이 같아도 의미가 다르면 Data Element를 구분

역분개 전표 조회 화면에 회계 전표번호와 원전표 번호가 함께 나온다고 가정

| 필드 | 기술적 형식 | 업무 의미 |
|---|---|---|
| 회계 전표번호 | CHAR 10자리 | 지금 조회 중인 전표의 번호 |
| 원전표 번호 | CHAR 10자리 | 이 역분개 전표가 취소한 원전표의 번호 |

두 필드는 같은 Domain을 참조해 10자리 문자 형식을 공유 가능,
하지만 Data Element를 각각 정의하면 화면에는 회계 전표번호와 원전표 번호라는 별도 라벨을 줄 수 있고, 도움말에서도 각 번호가 어떤 전표를 가리키는지 설명 가능함.

## 요약
재사용할 때는 “두 필드에 같은 라벨과 설명을 붙여도 의미가 정확한가?”를 고민한다.

- 전표 저장용 회사코드와 조회용 회사코드는 같은 업무 개념이므로 Data Element를 재사용 가능함.
- 회계 전표번호와 원전표 번호는 기술적 형식을 공유하면서 각 필드의 역할을 별도 Data Element로 표현 가능.
